Resumen. Este manual recopila, en el orden exacto en que se ejecutaron, todos los comandos empleados para verificar, empaquetar, subir y publicar la plataforma en el servidor. Cada bloque indica dónde se ejecuta, qué hace y qué resultado se obtuvo. Se incluyen también los cinco problemas que aparecieron durante el proceso y su solución, para que el procedimiento pueda repetirse sin volver a tropezar con ellos.

Convenciones y datos fijos

WIN = se ejecuta en PowerShell de tu Windows, dentro de C:\Plataforma Educativa.
SRV = se ejecuta en el servidor Linux por SSH.
OK = resultado que se esperaba y se obtuvo.
ERR = incidencia aparecida, resuelta más adelante.

3. Firewall: apertura de puertos

sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status

El puerto 80 es necesario para que Let's Encrypt emita el certificado; el 443 sirve la web cifrada; el 22 se añadió para no perder el acceso SSH al activar el firewall. Al activarlo aparece la advertencia Command may disrupt existing ssh connections: se respondió y.

OK Salida final de sudo ufw status:

Status: active

To                         Action      From
--                         ------      ----
80/tcp                     ALLOW       Anywhere
443/tcp                    ALLOW       Anywhere
22/tcp                     ALLOW       Anywhere
80/tcp (v6)                ALLOW       Anywhere (v6)
443/tcp (v6)               ALLOW       Anywhere (v6)
22/tcp (v6)                ALLOW       Anywhere (v6)
Advertencia. Justo después de las dos primeras reglas, sudo ufw status mostraba Status: inactive. Eso era normal: las reglas quedaron guardadas pero no aplicadas hasta ejecutar sudo ufw enable.

3.1 Comprobación de puertos ocupados

sudo ss -tulpen | grep -E ':80|:443'

ERR Apareció nginx escuchando en 80 y 443 dentro de un contenedor. Se identificó con docker ps (sección 4) y se paró su contenedor en la sección 5.

7. Incidencia del 403 y su corrección

7.1 Síntoma

curl -I https://sistematizacion.itsoeh.edu.mx/
# HTTP/2 403   content-type: text/plain   via: 1.1 Caddy

curl -sS -i https://sistematizacion.itsoeh.edu.mx/
# Blocked request. This host ("sistematizacion.itsoeh.edu.mx") is not allowed.
# To allow this host, add it to `preview.allowedHosts` in vite.config.js.

Causa: Vite 8, usado por vite preview dentro del contenedor del frontend, rechaza cualquier cabecera Host distinta de localhost por seguridad. El backend y el login ya funcionaban correctamente.

7.2 Corrección aplicada en el servidor

cd /opt/plataforma-educativa
cat > infrastructure/compose/Caddyfile <<'EOF'
{
    email admin@{$DOMAIN}
}

{$DOMAIN} {
    encode zstd gzip

    handle /api/* {
        reverse_proxy backend:8000
    }

    handle /docs* {
        reverse_proxy backend:8000
    }

    handle /redoc* {
        reverse_proxy backend:8000
    }

    handle /openapi.json {
        reverse_proxy backend:8000
    }

    handle {
        reverse_proxy frontend:5173 {
            header_up Host localhost
        }
    }
}
EOF
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml restart proxy

La línea header_up Host localhost hace que Caddy presente el frontend como si la petición viniera de localhost. El navegador sigue usando el dominio real. El comillas en <<'EOF' son importantes: evitan que la shell interprete {$DOMAIN}.

7.3 Comprobación inmediata

curl -I https://sistematizacion.itsoeh.edu.mx/
# HTTP/2 200   content-type: text/html

curl -s https://sistematizacion.itsoeh.edu.mx/openapi.json | head -c 200
# {"openapi":"3.1.0","info":{"title":"Plataforma Educativa API",...
Advertencia. La ruta correcta es /openapi.json. La ruta /api/v1/openapi.json devuelve {"detail":"Not Found"} porque FastAPI publica el esquema en la raíz. Ya está corregida en DEPLOY.md y en la guía en PDF.

9. Comandos de operación diaria

cd /opt/plataforma-educativa

# Estado de los contenedores (usar sudo si el grupo docker aún no está activo)
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml ps

# Ver logs en directo (Ctrl+C para salir)
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml logs -f proxy
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml logs -f backend

# Reiniciar un servicio
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml restart backend

# Parar sin borrar datos
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml down

# Borrar también la base de datos (reinicia los usuarios de prueba)
sudo docker compose --env-file .env -f infrastructure/compose/compose.prod.yaml down -v

# Actualizar tras copiar cambios al servidor
sudo bash infrastructure/deploy.sh
Advertencia. No arranques thingsboard-proxy mientras Caddy esté ocupando 80 y 443, porque chocarían por los puertos. Si necesitas recuperar ThingsBoard web, hay que reorganizar el proxy.
